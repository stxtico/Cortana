# A13 — CAD training-data pipeline

Moved verbatim from CLAUDE.md's Done log (2026-08-12 restructure) — see

- **A13 — CAD data pipeline (`cad/verified/`, `scripts/cad_log.py`,
  `scripts/cad_synth.py`), no model involved.** Checked CadQuery's real
  install compatibility before writing anything against it, per the explicit
  instruction and this project's own track record of dependency friction on
  every third-party integration so far: `uv add cadquery` (2.8.0, pulling
  `cadquery-ocp` 7.9.3.1.1 - the actual OpenCascade bindings - plus `vtk`,
  `casadi`, `nlopt`, `ezdxf`) resolved and installed clean, zero touches to
  the already-pinned `numpy<2.5`/`transformers<5.1`/`torch` versions
  (confirmed by diffing `uv.lock` and re-importing all three afterward -
  identical versions, `torch.cuda.is_available()` still `True`). VRAM was
  never actually a real risk here - CadQuery/OpenCascade is a pure-CPU
  geometry kernel, no GPU path at all - but confirmed rather than assumed.
  **Shared verification, one real definition, not two**:
  `scripts/_cad_common.py`'s `verify_solid()` is what both `cad_log.py`'s
  `add-part` and `cad_synth.py`'s per-variant check call - execute, check
  `isValid()` (watertight), check volume > 0, **and** attempt a real STEP
  export to a throwaway temp file. That last check isn't redundant with
  `isValid()` - PLAN.md's own stated output format is "CadQuery... exports
  STEP", so a solid OCCT calls valid but can't actually export wouldn't be a
  usable pair either. `part.py`'s contract: `def build(**params) ->
  cq.Workplane`, numeric keyword defaults define both the canonical
  hand-written part and (absent an explicit range in `meta.json`) the
  center of `cad_synth.py`'s fallback +/-25% variant range.
  **`cad_log.py add-part` actually executes and verifies the script before
  accepting it** - refuses with a clear reason otherwise, so nothing
  unverified can land in the library (PLAN.md's explicit guard-against).
  Verified this refusal for real, not just by reading the code: wrote a
  bracket variant with `hole_inset` (8.0) exceeding `width`/`height` (5.0),
  confirmed it genuinely raises `StdFail_NotDone` from OCCT (the hole
  cutter doesn't intersect the flange), confirmed `add-part` refuses it and
  leaves no partial directory behind, then logged it for real via
  `add-attempt` - `attempts.jsonl` holds the actual failing script and a
  real explanation, not a placeholder.
  **The hand-written part**: an L-bracket (`cad/verified/bracket/`) - a
  horizontal base flange and vertical upright flange joined with an inner
  fillet, one mounting hole per flange. Built and tested interactively
  against the real installed CadQuery before committing to a design (fillet
  edge selection and hole placement both needed real iteration - a
  `NearestToPointSelector` for the fillet edge and explicitly-placed cutter
  cylinders for the holes turned out more robust across the parameter range
  than face selectors like `>Z`, which can become ambiguous once
  width/height/thickness change relative order). Stress-tested 50 random
  parameter combinations before treating the design as done: 50/50 valid.
  **`cad_synth.py`'s dataset entries are self-contained, not relative
  references**: each `cad/dataset.jsonl` line embeds a full standalone
  script (the base part's source plus an explicit `RESULT = build(...)`
  call with that variant's exact values), not just a params dict pointing
  back at `part.py` - reproducible on its own even if the base script's
  defaults change later. Verified this is genuinely true, not just
  structurally plausible: took 5 random records' `script` field, `exec()`'d
  each fresh (no reuse of any pipeline internals), and confirmed the
  resulting solid's volume matched the recorded value exactly and was still
  valid. Also confirmed all 200 generated variants' parameters actually
  fell within `meta.json`'s declared ranges (0 violations) - the
  random-sampling logic wasn't silently drifting outside its own stated
  bounds.
  **Done-when, exceeded**: `uv run scripts/cad_synth.py bracket -n 200
  --seed 42` produced 200/200 verified pairs (0 discarded) in ~9 seconds
  against the one hand-written bracket - double the 100+ target, with
  meaningful margin since not every synth run will land 100%. `cad/dataset.
  jsonl` gitignored (synthetic, mechanically regenerable from
  `cad/verified/` + `cad_synth.py` in seconds - same "generated/accumulated
  state stays out of git" pattern as `logs/`/`memory_store/`/
  `daemon_store/`); `cad/verified/` itself (hand-authored scripts,
  descriptions, and real failed-attempt history) is tracked.
